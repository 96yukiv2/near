# これからの機能と確認

無料枠で進めます。有料契約やプラン変更が必要な場合は事前に知らせます。秘密情報はチャットに貼らず、サービス側に設定します。

## 今回の Web 版

- **トップと地図**：トップに Near の説明とログイン・地図への入口を配置。地図の色味と画面を調整し、位置の一覧から名前を選ぶとその場所へ地図が移動する。共有停止・友達削除・ブロック後に取得できない権限は DB で制御する。
- **アイコン**：写真をアップロードせず、用意されたアイコンから選択する。表示名と一緒に保存し、承認済みの友達一覧と、位置の閲覧を許可された地図に表示する。アイコン用 DB マイグレーションは開発環境に反映済み。
- **費用と地図**：OpenStreetMap のベクタータイルを明るい配色で表示し、読み込めない場合は標準画像タイルへ切り替える。契約やキーは不要。ベクタータイルは無償だが可用性の保証はなく、[利用条件](https://operations.osmfoundation.org/policies/vector/)とアクセス量を確認する。`NUXT_PUBLIC_MAP_STYLE_URL` でスタイル URL を変更できる。

## 公開・実利用までの残作業

1. **友達・位置の権限確認**：2 人以上のテストアカウントで招待・承認・共有・停止・削除・ブロックを確認する。未ログイン、未承認、友達の友達、他人の位置更新を含む API 直接テストも実施する。CI では一時停止中。
2. **認証**：パスキーの実機での登録・ログインを継続して確認する。Supabase 側の従来メール・パスワード認証は停止済み。LINE 内ブラウザで動かない場合は Safari などのブラウザで開く。
3. **アカウント復旧**：メール確認と復旧コードは実装済みだが、メール送信サービスは未設定。復旧後の Supabase セッション削除と、古いトークンを Near の API で拒否する対策は実装済み。新しいパスキー保存後に失効処理が失敗する場合の安全な処理と、マイグレーションの適用状態を確認する。無料のメール送信手段の設定と実際の Supabase を使ったセキュリティ検証が完了するまで復旧機能は無効のままにする。
4. **削除**：パスキー認証側と Supabase 側の削除、位置・友達関係の削除、途中失敗後の再試行を実際のテストアカウントで確認する。
5. **地図とデザイン**：さまざまなスマホ幅で操作を確認し、地図やパネルの調整を続ける。写真アップロード方式のアイコンは未対応。別の地図スタイルを使う場合は無料枠、条件、帰属表示を再確認する。
6. **自動テスト**：CI では Vitest の単体テストを実行している。API 権限テストは CI では実行していない。位置情報を友達以外に渡さないことは画面確認だけでは保証できないため、実利用前に権限テストを再開する。

## モバイルアプリ

- **実装済み**：Expo の雛形、パスキー認証、プロフィール、友達管理。Android の地図とバックグラウンド位置共有は PR #28 でレビュー中。
- **ユーザーによる設定と確認**：公開用 Supabase URL・publishable key と認証の Redirect URL を設定し、Pixel でログイン・権限・通知・共有の開始停止を確認する。[Pixel 実行手順](../apps/mobile/README.md#pixel-実機で実行する)を参照。
- **残りの実装**：招待リンクをアプリ内で受け取る導線、アカウントの復旧・削除のアプリ内操作、共有状態とエラー表示の改善、Android 向け配布用 APK と署名手順。復旧機能は Web 側の安全性確認が済むまで有効化しない。
- **安全性・配布**：複数アカウントで位置の取得制限、停止・友達削除・ブロック、通信失敗やアプリ停止時の動作を確認する。Android App Links とバックグラウンド更新の OS 制限、電池消費を検討する。iOS の実装・配布は後回し。

実装・設定は AI が進め、サービスのアカウント作成や実機確認など AI ができない操作はユーザーにお願いする。認証の詳細は [パスキー認証](passkey-auth.md)、権限の設計は [設計](design.md) を参照。
