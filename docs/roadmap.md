# 今後のステップ

実装・設定は AI が進め、アカウントへのアクセス承認や実機での確認など、AI ができないことをユーザーにお願いします。秘密キーやパスワードをチャットに貼る必要はありません。有料契約やプラン変更は行わず、必要になった場合は事前に伝えます。

## 1. ドキュメントと現状の整理

- AI: 実装状況、利用できる機能、未完了事項を現状に合わせる。
- ユーザー: ドキュメントの PR をレビューする。

## 2. パスキー認証の接続

- AI: 認証用 DB ロールと OIDC 接続を用意し、Supabase と Vercel の設定を進める。実施できない権限操作があれば、具体的に内容と手順を伝える。公開用 URL と WebAuthn の RP ID、Preview のアクセス保護を確認する。
- ユーザー: 求められた場合のサービス連携・アクセス承認と、パスキー登録・ログインの実機確認を行う。
- 完了条件: パスキーで登録・ログインし、Supabase 上でも同じ利用者として認証される。未確認の間、認証フラグは無効のままにする。

## 3. 復旧とアカウント削除

- AI: メールと復旧コードを組み合わせた復旧の安全性を確認する。復旧メールを使う場合は無料で利用できる送信手段と条件を確認し、設定と必要な修正を行う。両認証基盤にまたがる削除と失敗時の再試行を確認する。
- ユーザー: 提案された復旧方法と費用条件を確認し、必要なメールサービスの連携と実機確認を行う。
- 完了条件: 採用した復旧方法と制約が明確になり、削除で関連する位置情報も消えることを確認する。

## 4. 安全な切り替えと Web 版の確認

- AI: Better Auth 経由の Supabase 認可を検証し、従来のメール・パスワード認証を Supabase 側でも無効にする。未ログイン、未承認、友達以外、友達削除・ブロック、共有停止、他人の位置更新を確認する。地図と各サービスの無料枠・利用条件を確認し、必要な修正を PR にする。
- ユーザー: Vercel でスマホの画面、位置許可、招待から友達追加、共有・停止をテストアカウントとダミー位置を基本に確認する。必要に応じて実機の位置情報も確認する。
- 完了条件: 目的のパスキー認証と位置共有が実環境で動き、友達以外から位置を取得できない。未検証のまま実際の位置を共有しない。

## 5. モバイルアプリ

- AI: Web の完成後に Expo アプリを設計・実装する。バックグラウンド位置共有と OS の制限、Android のプレビュー配布を検討する。iOS の無料実機テストと有料の配布方法を分けて調べる。
- ユーザー: 実機確認、必要なアカウント設定、配布方法の判断を行う。

## 現在のサービス設定

- 開発用 Supabase にはプロフィール・友達・位置共有・認証用テーブルを作成済み。認証用の専用 DB ロールは作成済み。接続は未確認。
- Vercel の本番とテスト用プロジェクトに Supabase の URL と公開キーを設定済み。テスト用の DB 接続を設定済みだが、パスキー認証に必要な設定と検証は未完了。
- 削除用 Edge Function は開発用 Supabase に未デプロイ。
- 復旧メールは未設定。登録した場合はメールアドレスを保存する。復旧には事前に保存した復旧コードも必要。実環境での検証が完了するまで無効。

環境設定や認証の詳しい説明は [パスキー認証](passkey-auth.md) を参照してください。
