# 設計

## 基本方針

承認した直接の友達同士だけが位置を共有できます。共有は初期状態でオフにし、ユーザーが開始・停止を選びます。位置履歴は保存せず、最新位置だけを上書きします。位置データはエンドツーエンド暗号化されていません。

Web は Nuxt と MapLibre、DB とアクセス制御は Supabase PostgreSQL と RLS / 限定された DB 関数を使用します。モバイルアプリは Web 版の後に追加します。必要なものだけ共通化し、秘密キーをブラウザやアプリに含めません。

## 認証

目標は Better Auth のパスキー認証と Supabase Auth のカスタム OIDC を組み合わせ、登録時の実メールアドレスとパスワードを不要にすることです。本人を区別する ID とパスキーの公開鍵などは保存されます。パスキーの秘密鍵は端末側にあります。認証機能は実装済みですが、接続設定と実環境での検証が完了するまで無効です。

復旧用メールは任意です。登録時にメールアドレスを保存し、復旧時はメールへの確認コードに加え、利用者が事前に保存した復旧コードを確認します。復旧コードはランダムに生成し、サーバーにはハッシュだけを保存します。いずれかを失うとこの方法では復旧できず、復旧コードは使用後に再発行が必要です。実環境での復旧検証が完了するまで有効化しません。メール・パスワード認証は移行後に Supabase 側でも無効にする方針です。

## データとアクセス制御

- プロフィールはユーザー ID と表示名を保持します。
- 招待はランダムなトークンのハッシュを保存し、24 時間・1 回限りです。招待を受けた人が申請し、作成者が承認すると友達になります。
- 友達関係とブロックは直接のユーザー同士の関係として保持します。ブロック時は友達関係と保留中の申請を取り消します。
- 位置と共有状態は `private` スキーマに保存し、認証済みの呼び出し元を検証する限定された DB 関数を通して操作します。書き込みは本人に固定し、読取は本人または直接の友達に制限します。停止時は最新位置も削除します。
- 友達関係が A-B、B-C にあっても、A-C 間に直接の友達関係がなければ互いの位置は取得できません。未認証、未承認、友達以外、共有停止、友達削除、ブロック、他人の位置更新もサーバー側で拒否します。
- アカウント削除時は本人を認証・認可し、関連データの削除を行います。Better Auth と Supabase にまたがる削除は実環境での確認が必要です。

すでに受信した位置情報を相手の端末から消すことは保証できません。位置を必要以上にログへ出力しない方針です。

## 画面と位置更新

表示名、地図、友達一覧と招待、共有開始・停止、アカウント設定を設けます。位置許可は共有開始時に求め、更新時刻と精度を表示します。15 分以上更新されていない位置は古い位置として区別します。

Web では位置画面を開いている間に定期送信します。タブを閉じても共有は自動停止しません。バックグラウンド共有はモバイル版で OS の制限を含めて別途検討します。

## テストと公開

CI は lint、formatter、型チェック、重要な単体テスト、ビルド、ローカル Supabase の API 権限テストを実行します。実際の端末の位置許可、Better Auth と Supabase の接続、復旧、削除は実環境でも確認します。API の公開キーは公開前提で扱い、サーバーの秘密情報は公開しません。

[今後のステップ](roadmap.md) に担当と順番を、[パスキー認証](passkey-auth.md) に設定の詳細を記載します。無料枠と提供条件は変わるため、利用開始前に確認し、有料契約やプラン変更はユーザーが判断します。
