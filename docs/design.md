# 設計と実装ステップ

## 進め方

各段階で動くものと確認方法を揃え、レビュー後に次へ進みます。無料枠・提供条件は変わるため、契約・公開前に公式情報で確認します。有料契約やプラン変更は依頼者の判断を待ちます。

1. **画面と開発基盤（今回）**: 架空データの地図、友達一覧、共有状態の見た目。Nuxt、lint、formatter、型チェック、テスト、CI、Dependabot。外部アカウント不要。
2. **認証とプロフィール**: Supabase のローカル環境を用意し、メール登録・ログイン・再設定・ログアウト、表示名の設定を検証。Google OAuth はプロバイダーの設定後に確認。同一メールの自動リンク条件、メール検証の扱いを Supabase の現行仕様と実機で確認し、意図しないアカウント統合を防ぐ。
3. **招待と友達**: 期限付き・推測困難な招待、受諾、友達削除、ブロック。直接 API を呼ぶ権限テストを先に用意する。
4. **位置共有**: 初期オフ、明示的な許可後の HTTP 位置更新、定期取得、停止、最終更新・精度・古さを表示。架空の座標とテストアカウントで RLS を検証してから実機確認する。
5. **削除と公開準備**: アカウント削除と関連情報の消去、認可・運用確認、Vercel 等への公開手順。Supabase、ホスティング、地図、認証メールの無料枠と規約を確認。
6. **モバイル**: Expo で同じアカウント・DB を使用。OS のバックグラウンド制限を検討。Android プレビュー配布、iOS の無料実機テストと有料 Ad Hoc / TestFlight を別々に検討し、Expo の無料枠も確認。

## データモデル案

- `profiles`: `auth.users` に紐づく ID と表示名。友達や招待に必要な範囲のみ公開。
- `invites`: 作成者、ハッシュ化したランダムトークン、有効期限、利用状態。トークンの平文はリンク発行時のみ提示し、期限・自己招待・再利用をサーバーで検証。
- `friend_requests`: 申請者、相手、状態。リンクを開くだけで友達にせず、相手の明示的な承認が必要。受諾と友達作成は原子的に処理。
- `friendships`: ユーザー ID のペアを正規順序で一意に保持。直接の関係だけを表す。
- `blocks`: ブロックした人とされた人。ブロック時は友達関係と保留中の申請を削除し、双方のアクセスを遮断。
- `location_settings`: 所有者と共有状態。初期値はオフ。
- `locations`: 所有者を主キーとした緯度・経度・精度・取得時刻。上書きのみで履歴を保存しない。削除はユーザー削除に連動。

実際のマイグレーションでは制約、競合時の原子性、インデックス、公開列、削除伝播を検証します。招待の承認方向や再利用ポリシーは実装時に UI と一緒に明確化します。

## アクセス制御

RLS と最小権限を基本とし、クライアントの画面表示には依存しません。位置の SELECT は認証済み本人、または共有オンかつ直接友達で双方にブロックがない相手に限定します。A-B、B-C の関係から A-C のアクセスを導かないことを直接 API で検証します。位置の INSERT / UPDATE / DELETE は本人だけに許可し、所有者 ID の変更も防ぎます。共有停止・友達削除・ブロックは以降の取得を即座に拒否します。取得済みデータの相手端末からの消去は保証できません。

招待や友達の変更は安全な DB 関数または認証・認可を確認する Edge Function で行い、直接書き込みを制限します。サービスロール等の秘密鍵はクライアントに置きません。アカウント削除には本人確認済みの Edge Function を使い、Auth ユーザーと関連データの削除を検証します。公開キーは公開情報として扱い、RLS で保護します。

API 権限テストでは未ログイン、未承認、直接友達、友達の友達、他人の更新、共有停止、削除、双方のブロック、アカウント削除を独立したアカウントで確認します。位置を必要以上にログへ出力しない方針です。

## 画面構成

ログイン・登録・再設定、表示名設定、地図と友達一覧、招待の作成・承認、友達詳細と削除・ブロック、共有設定、アカウント削除。位置許可は共有開始時に求め、拒否時や古い位置、通信エラーも説明します。今回の画面は方向性を確認するためのデモで、未実装の機能を実際に操作できるとは示しません。

## サービス設定

依頼者が Supabase・Google OAuth・Vercel 等のアカウント作成と連携を担当します。必要な時点で設定手順とコールバック URL を案内します。秘密鍵やパスワードをチャットに貼る必要はありません。認証メールの送信制限、OAuth の条件、タイルの無料枠・帰属表示・使用制限、Vercel と Supabase の無料枠は公開前に公式情報で確認します。
